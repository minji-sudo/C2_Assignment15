# 과제 15: 퀵 정렬과 AVL 트리 정렬의 성능 비교

## 1. 개요

같은 무작위 정수 데이터를 퀵 정렬(배열) 과 AVL 트리 로 각각 정렬한 뒤, 데이터 크기 n의 20%만큼 삽입·삭제를 반복했다. 정렬부터 삽입·삭제가 모두 끝날 때까지의 총 수행시간, 비교 횟수, 데이터 이동 횟수, 메모리 사용량을 비교했다.


## 2. 구현 방법

| 구분 | 내용 |
|---|---|
| 퀵 정렬 | 피벗은 Median-of-Three(첫·중간·끝 원소의 중앙값) 사용. Lomuto 파티션, 재귀. 구간의 원소가 2개일 때는 `mid == lo` 라서 Median-of-Three가 자기 자신과의 비교와 같은 쌍의 중복 비교(3번)를 하게 되므로
비교 1번 후 필요하면 교환하고 바로 끝낸다 |
| 배열 삽입 | 정렬된 배열을 앞에서부터 선형 탐색해 처음으로 x보다 큰 위치를 찾고(같은 값 뒤에 삽입), 그 뒤 원소들을 한 칸씩 뒤로 이동 |
| 배열 삭제 | 앞에서부터 선형 탐색으로 x 이상인 첫 원소를 찾고(정렬되어 있으므로 거기서 중단), 값이 같으면 뒤 원소들을 한 칸씩 앞으로 이동. 없으면 삭제하지 않음 |
| AVL 트리 | 노드 = `key, count, height, left, right`. 중복 값은 새 노드를 만들지 않고 `count`만 증가 |
| AVL 삽입 | BST 삽입 후 되돌아오며 높이 갱신·균형 인수 확인, 필요하면 LL/LR/RR/RL 회전 |
| AVL 삭제 | `count > 1` 이면 `count--` 만 수행(한 개만 제거). 마지막 한 개면 노드 제거: 자식 0~1개는 자식으로 대체, 자식 2개는 중위 후속자의 `key, count`를 복사한 뒤 후속자 노드를 제거. 이후 회전으로 균형 복구 |

실험 조건

- 값 범위는 `0 ~ 2n-1` 이다. 값 범위를 고정(예: 0~99,999)하면 n=1,000에서 임의의 삭제 값이 존재할 확률이 1% 정도라 삭제가 거의 일어나지 않기 때문에, 삭제가 실제로 일어나고 중복도 생기도록 n에 비례시켰다.
- 연산 선택은 난수가 짝수이면 삽입, 홀수이면 삭제이고, 삽입·삭제할 값은 별도 난수이다. 연산 목록(종류와 값)은 미리 한 번 생성해서 두 자료구조가 똑같이 사용한다. (난수 생성 시간은 측정에서 제외)
- 삭제할 값이 없으면 건너뛴다. 이 경우에도 값을 찾느라 비교는 발생한다.
- 시드를 2024로 고정해서 결과를 재현할 수 있다.

검증 (시간 측정 이후에 수행하며 카운터에는 영향 없음)

1. 정렬 직후: 퀵 정렬 결과가 오름차순이고, AVL 중위 순회 결과(`count`만큼 펼침)와 같은지 확인
2. 모든 연산 후: 배열이 오름차순이고, AVL 중위 순회 결과와 원소 하나하나까지 동일한지, 원소 수와 삭제 성공 횟수가 같은지 확인
3. AVL의 높이 값과 균형 인수(-1~1)가 모든 노드에서 올바른지 확인

모든 크기에서 검증을 통과했다.

## 5. 비교·분석

### 5.1 총 수행시간과 비교 횟수

모든 크기에서 AVL 트리가 시간과 비교 횟수 모두 적었고, n이 커질수록 격차가 벌어졌다. n = 20,000 에서 총 시간은 배열이 129.2ms, AVL이 7.3ms로 약 17.8배, 비교 횟수는 약 4,092만 회 대 31만 회로 약 132배 차이가 났다.

원인은 삽입·삭제 단계에 있다. 정렬된 배열은 삽입·삭제 위치를 찾으려고 선형 탐색을 하므로 연산 한 번에 평균 n/2 정도의 비교가 필요하다. n = 20,000 에서 삽입·삭제 4,000회의 비교가 40,606,777회이므로 연산당 약 10,150회로,
n/2 = 10,000 과 거의 일치한다. 반면 AVL은 같은 4,000회에 55,606회, 즉 연산당 약 13.9회였고, 이는 노드 수 16,323개의 `log₂` ≈ 14 와 같은 수준이다. AVL은 높이가 `O(log n)` 으로 유지되기 때문에 탐색 경로 길이가 곧 비교 횟수가 된다.

반대로 정렬 단계만 보면 결과가 다르다. 비교 횟수는 AVL 구축이 254,833회로 퀵 정렬(311,077회)보다 적었지만(약 0.8배), 시간은 AVL 5.58ms, 퀵 정렬 1.77ms로 AVL이 약 3.1배 느렸다. 비교는 적어도 AVL은 노드를 하나씩 `malloc` 하고, 
재귀로 내려갔다 올라오며 높이를 갱신하고 균형을 확인하고, 흩어진 노드를 포인터로 따라가야 한다. 퀵 정렬은 연속된 배열을 순차적으로 훑는 단순한 연산이라 비교 한 번당 비용이 훨씬 작은 것으로 보인다.
즉정렬 하는 상황에서는 퀵 정렬이 유리하고, AVL의 이점은 정렬 이후 삽입·삭제가 이어질 때나타난다. 

### 5.2 삽입·삭제 과정의 데이터 이동 횟수

이동 횟수 차이는 비교 횟수보다 더 컸다. n = 20,000 에서 배열은 29,123,533회, AVL은 39,524회로 약 737배 차이가 났다.

배열은 값을 삽입하거나 삭제하면 그 위치 뒤의 원소를 전부 한 칸씩 밀어야 한다. 삽입 1,978회와 삭제 성공 775회에서 삽입·삭제 단계의 이동이 28,574,878회이므로, 실제로 수정이 일어난 연산당 약 10,380회로 n/2(10,000) 근처이다.
존재하지 않는 값의 삭제 시도(1,247회)는 탐색만 하고 이동은 하지 않았다. AVL은 값 자체를 옮기지 않고 노드의 포인터만 연결하므로, 삽입·삭제 단계 전체 이동이 3,811회, 연산당 약 0.95회였다
정렬 단계에서도 퀵 정렬은 교환(대입 3회)이 많아 548,655회, AVL 구축은 35,713회(약 15배 적음)였다.

### 5.3 메모리 사용량

메모리는 반대로 AVL이 약 5배 안팎으로 더 많이사용했다(n = 20,000: 배열 96,876B, AVL 523,412B).
배열은 원소당 `int` 4B만 필요하고, 배열 할당 크기(n + 삽입 최대 횟수)가 대부분이다. 퀵 정렬의 재귀 스택은 최대 깊이가 23단계, 약 830B라 전체의 1% 정도였다.
AVL은 노드마다 `key, count, height`와 포인터 2개를 가지므로 노드당 32B이고, 최대 노드 수 16,323개 × 32B = 522,336B에 재귀 스택(최대 18단계) 약 1KB가 더해졌다.
이 5배 안팎의 비율은 n이 달라져도 4.9~5.4배로 거의 일정했다. 

### 5.4 데이터 크기 증가에 따른 성능 변화

n이 20배(1,000 → 20,000)가 되는 동안 변화량은 다음과 같았다.

| 항목 | 배열(Quick) | AVL |
|---|---:|---:|
| 총 시간 | 약 364배 | 약 38.6배 |
| 비교 횟수 | 약 373배 | 약 30.3배 |
| 이동 횟수 | 약 343배 | 약 20.3배 |

배열은 n이 2배 될 때마다 비교 횟수가 약 4배씩 늘었다(4,000 → 8,000: 1,694,741 → 6,797,245회, 약 4.0배). 삽입·삭제 횟수가 n에 비례하는 데다 연산 한 번의 비용도 n에 비례하므로 전체가 `O(n²)` 으로 증가한 것이다.
AVL은 비교 횟수가 20배에서 30배 정도로, `n log n` 이론값(약 28.7배)과 거의 같았다. 배열의 총 시간 증가(약 364배)도 비교 횟수 증가(약 373배)와 거의 같다.
AVL은 시간이 약 39배로 비교 횟수 증가(30배)보다 더 늘었다.
